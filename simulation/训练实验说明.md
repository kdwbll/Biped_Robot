# 双足仿真：理论舵机与探索性训练

## 目的和界限
本工程只适合验证代码、碰撞近似和探索性强化学习流程；未证明可以走路、优于作者的步态或部署实物。不要将脉宽范围、力矩或策略直接用于实机。

## 本次选取的理论值
- 舵机：假设 270°位置型、500–2500 μs、中心1500 μs；商品图中的180°标签与所选270°选项不一致，需后续实物确认。
- 6V 商品图标称 0.26 秒/60°空载速度，即约4.03 rad/s；24 kgf·cm 堵转力矩按9.80665换算约2.354 N·m。堵转值不是持续安全力矩。
- 50 Hz 更新；转速限制和线性力矩-速度关系为人为简化，PD增益 kp=1 N·m/rad、kd=0.08 N·m·s/rad 未实测。每个舵机安装方向和中心位置暂以初始姿态为基准。
- 单次训练动作5维，映射成初始中心附近的1420–1580 μs；控制器仍对完整脉宽范围裁剪。上部/膝部轴和23:50转向传动仍是候选映射。
- 质量：实心打印件密度1.24 g/cm³，5个舵机各55g，12根暂定4mm×90mm轴按304钢8.0g/cm³；总约2.94kg，不含电池及线材，惯量为包围盒近似。

## 碰撞状态
`biped_filtered_collision_experimental.xml` 给两腿、膝部、部分机身、上部及假设销轴增加凸碰撞体；相连关节的接触对有意排除。分解后的塔架与机身在初始姿态出现较大近似碰撞，实验性自动排除了55个初始重叠的塔架-机身接触对，仍有约0.207mm初始接触重叠。SolidWorks原CAD干涉检查报告7处实际相交，主要位于上部齿轮/机身等，需后续核对。不能声称碰撞已经完整准确，轴长、齿轮齿形、相连件和摩擦仍有近似。

## 文件与运行
- `theoretical_servo.py`：6V理论位置伺服近似。
- `biped_env.py`：Gymnasium 训练环境；重置会加载 `centered_start`，每步20ms，假设前进方向为模型+X。
- `train_ppo.py`：PPO实验；例如 `.venv\Scripts\python.exe train_ppo.py --timesteps 4096 --output ppo_experiment_4096`。
- `view_ppo.py`：观看仿真策略，运行 `.venv\Scripts\python.exe view_ppo.py ppo_experiment_4096.zip`；只适用于仿真。
- `test_biped_env.py`、`test_theoretical_servo.py`、`test_collision_coverage.py`：接口、理论舵机、部分碰撞的测试。

训练奖励同时考虑前进、保持直立、动作大小及变化；数值仅为实验选择，尚未证实会产生自然行走。当前没有领域随机化；多次评估仅重复相同确定性初始条件，不是鲁棒性或真实对比。

## 4096步 PPO 小规模实验（仅流程测试）
2026-10-31，本地CPU完成4096个环境步，训练文件 `ppo_experiment_4096.zip`。模型重置固定同一初始状态，没有领域随机化；3次评估完全相同，不是3个独立工况。4秒确定性评估：静止基线模型+X位移约0.537mm，PPO约0.487mm，两者均未触发摔倒，PPO没有胜过静止基线，也没有证明行走。
`biped_filtered_collision_experimental.xml` 包含9539个显式接触对，初始17个接触，最深近似接触重叠约0.207mm；为避免粗凸包导致明显假干涉暂排除55组塔架/机身碰撞，SolidWorks原始装配体检测到7处干涉（部分可能是齿轮啮合等预期接触，尚未逐项确认）。因此碰撞不是完全解决，不应视为可靠实物仿真。理论舵机测试的两秒小动作曾发生倾倒，不能把无摔倒的中立测试当作稳定控制保证。
可双击 `查看训练实验.bat` 或在项目目录运行 `.venv\Scripts\python.exe view_ppo.py ppo_experiment_4096.zip`。该演示仅运行模拟，策略动作很小且看不出有效行走。

## 双腿侧倾诊断和可回退对照实验
两腿软件舵机理论参数共用同一份 ServoSpec，但CAD质量并不完全一致：不含销轴时 L0 约1.01285 kg、L1约0.97425 kg，相差约38.59g。顶部 part0 差约41.61g，其中 41.535g 来自 L0 有、L1 未检测到的一块约85×85×19mm实体。是否为真实缺件或设计差异尚未确认。
对照实验 biped_mirrored_part_centered_experiment.xml 在 L1 添加镜像候选实体的可见网格与41.535g质量，并重算初始居中姿态；该补充体的碰撞未建模，仅为假设，不改原始CAD或原模型。约0.573度初始侧倾，原来约0.800度。两者各在固定初始条件下模拟4秒：中立理论控制最大绝对横滚约0.869°（原）与0.581°（实验）；同一个4096步策略分别约1.715°与0.953°，都未触发45°摔倒条件。这不是可重复鲁棒性测试；策略换质量后效果不一定可靠。
同一初始姿态不重新对齐的仅加质量对照下，旧策略出现约43.2°横滚，说明姿态、接触与策略耦合明显，不能单凭质量差认定实际倾倒原因。每模型重置后从1秒至3秒，实验中腿部与地面法向力均值：原约17.187 N vs 14.895 N；重算姿态的补件实验约14.801 N vs14.244 N。接触为代理、单工况，不能替代真实压力测量。直接使用原生 Viewer 不会自动执行 Python 模型舵机保持控制器、也不总会加载关键帧，故不同窗口运行行为不可混同。
查看双腿对称实验.bat 运行中立舵机的可视化对照。未替换训练环境的默认模型或原始CAD。

## 训练迭代和虚拟辅助（2026-10-31）
PPO 使用 CUDA 训练小型策略网络，4 个环境的 MuJoCo 物理计算仍在 CPU。不同初始微扰的 5 次四秒评估均不施加虚拟辅助。`continued_gpu_49152_steps.zip` 在此前评估中均未倒地、平均前移约 13.8 mm，但未观察到有效抬脚；不能称为行走。后续多次迭代出现倾倒，不以较高位移当成功。

`probe_leg_kinematics.py` 将模型升高并关闭重力，检查单腿相对机身移动：在各腿所试的组合中，左/右最大上移约 35.9/37.9 mm。这只是无重力离地诊断，不代表负载下性能。`probe_weight_support.py` 在原地接触环境中施加虚拟平衡力矩与托举机身重量的力：在承担 80% 体重时，两侧指定动作分别出现约 6.75/9.71 mm 的短暂脚底离地，且记录到对侧脚接触；该辅助是额外的虚拟外力，实际机器人没有这个装置。

`train_support_curriculum.py`、`train_harness_curriculum.py` 只在训练时逐步减小虚拟辅助力矩和托举力，保存的审计文件使用完全无辅助的 `SteppingEnv`。`audit_walking.py` 独立记录双脚各自的支撑抬脚帧和事件；孤立接触事件仍需排除抖动并观看完整轨迹。由于物理模型、舵机参数和碰撞仍未经实物校验，以上仅为探索性仿真，禁止直接用于实物。

`probe_alternating_commands.py` 测试人工周期指令：虚拟吊带承担80%体重且有虚拟平衡力矩时，幅度1、周期1秒的试验在4秒内无摔倒、两脚最高分别离地约5.1/8.3毫米，但机身后退约23毫米。用 `pretrain_harness_teacher.py` 采集辅助示范并监督拟合得到 `assisted_imitation_start.zip`。`audit_imitation.py` 对3个初始扰动的评估显示：有80%辅助时均维持4秒并有左右抬脚，但后退约21–27毫米；无辅助时均在约1.34秒内因侧倾终止，尚未形成无辅助行走。接触事件存在抖动，不能简单将事件数当作完整步数。

可双击 `查看辅助抬脚演示.bat` 查看该策略；脚本明确施加80%托举和虚拟平衡力矩，每4秒重置。该演示不代表自主站立或行走。`train_harness_curriculum.py imitation` 从此策略继续强化学习并逐渐移除虚拟辅助，训练结果必须通过无辅助的逐脚审计。

## 较长站立测试与分阶段支撑实验
在无额外虚拟辅助、3个初始角速度扰动种子下，`continued_gpu_49152_steps.zip` 的20秒测试均未触发35°倾倒阈值，最大倾角约0.84°，机身向前滑移约22.7–24.2 mm；结果为单个候选模型和短时测试，不能证明实物或长时间稳定。详细数据见 `standing_20s_audit.json`。

`probe_standing_knee.py` 按当前模型每侧选取的上端、膝部、下端连接销轴计算初始几何夹角，相对于三点共线伸直的弯曲分别约38.77°和42.56°；这不是舵机转角，不是推荐安装角度，连接定义仍为候选。

`train_partial_support.py` 固定64%虚拟托举和相应姿态力矩，强化支撑脚接地时的摆动脚抬高奖励。从 `partial_gpu_49152_steps.zip` 评估3个扰动种子，有辅助时4秒均未跌倒，机身前移约18–21 mm，两脚均有超过3mm离地且对侧接触的记录；这不自动证明稳定连续步行。完全撤掉辅助时同样的3次均能保持4秒，但无有效抬脚。后续65536步检查点的无辅助测试均侧倾，因此保留49152步检查点，继续探索50%托举。`audit_residual_support.py` 的输出按辅助程度分别保存，避免误把辅助结果当作无辅助能力。

50%托举和虚拟平衡力矩下，`focusleft_gpu_131072.zip` 在3个扰动种子的4秒仿真中均未倒、前移约22.7–26.0 mm，两脚最大离地约5.5和10.1 mm；`audit_gait_sequence.py` 以至少连续3帧（60 ms）脚底高于3 mm且对侧脚接触定义抬脚，每次均记录7个左右交替事件。估算的接触中脚部几何中心累计移动约150–160 mm，是包含脚转动的代理指标，不能直接视为接触点滑动。完全无辅助的3次测试均在1.24秒侧倾终止，不能称为自主行走。该实验在现有近似碰撞和理想舵机上运行，不能用于真实机器人。

`view_live_checkpoints.py` 和 `查看实时训练检查点.bat` 独立回放最新已保存的指定分支检查点；仿真并非后台训练环境，默认同时施加相应的40%或50%虚拟托举和虚拟平衡力矩。已保存的50%示例 `focusleft_gpu_131072.zip` 保留作为可回退对照。

## 并行加速与自动阶段（2026-10-31）
`benchmark_parallel_envs.py` 的单次短测：4个CPU物理环境约259环境步/秒，8个约395环境步/秒。8环境完整PPO各4096步短测：CPU策略约388步/秒，CUDA策略约337步/秒。以上是单次特定负载结果，不保证每次均相同；当前小型策略网络用CPU更快，物理仍为CPU MuJoCo。

`train_fast_curriculum.py` 使用8个环境和CPU策略，从40%托举的 `partial40_gpu_163840.zip` 继续训练，新增独立扰动种子9101–9103评估。每32768步，在当前托举下3次均未摔倒、前移且至少3次左右切换才自动减少5个百分点托举，同时执行无辅助评估；训练保存检查点供查看器回放。40%检查点在此前3次短测中两脚峰值分别约4.3和3.6 mm、4秒未摔倒并前移约29–32 mm，但无辅助均约0.8秒侧倾；尚未证明稳定连续步态或实物能力。

`train_continuous.py` 持续运行8个CPU环境，每32768步评估并以原子替换方式保存 `continuous_current.zip`、`continuous_best.zip` 和 `continuous_state.json`；评估记录追加至 `continuous_audits.jsonl`。同一辅助阶段连续3轮未改善时，回到该阶段保存的较好策略并调整弱侧抬脚奖励；通过3个扰动种子的交替抬脚检查后，才减少5个百分点的虚拟托举。无辅助评估每2轮或通过阶段时进行。电脑休眠、关机或进程停止会中断训练；重新运行脚本从上一个已保存轮次恢复。双击 `停止持续训练.bat` 可以停止，当前未保存轮次会丢失。实时窗口只回放独立环境中的最新已保存策略，虚拟托举与平衡力矩仍然启用。

`查看四画面和训练进度.bat` 使用 `live_telemetry.py` 的Windows共享内存，每约0.15秒读取前4个真实训练环境的状态并重绘，不额外推进训练过程；界面显示数据延迟、托举比例、累计步数及最近评估。若训练停止，快照会变旧；渲染窗口会额外占用计算资源。`查看实时训练检查点.bat` 是另一个独立的检查点回放，两个窗口不应混淆。

2026-11-01：持续训练每回合上限由4秒延长至12秒（600个20毫秒控制步）；如果触发35°倾斜等终止条件仍提前重置。保留4秒评估作为与历史指标的对照，另外每两轮进行一个12秒带当前辅助的长程测试；评估数据中的 `longer_test` 独立记录。延长回合不保证模型能完成整个回合，也不等于实际自主行走。

## GPU物理加速探索（独立实验，未切换训练）
安装于 `warp_test_packages` 的MuJoCo Warp 3.17.0 / Warp 1.18.0已识别RTX 5060 Laptop 8 GB，并载入原候选模型的9539组显式碰撞对和18个等式约束。默认约束容量128出现溢出；测试提高为每世界 `nconmax=1024,njmax=4096` 后，在以下短测日志中未发现溢出提示。无控制器条件下CPU和GPU仿真1秒，状态保持有限，但 `qpos` 最大绝对差约0.0061（包含位置和角度分量，单位不同）；尚未证明舵机、接触及长时间动力学相同。

使用CUDA graph的64世界、每世界2000个无控制物理步微基准，约57241物理步/秒；这不含PWM舵机控制器、强化学习策略、奖励、观测、重置或可视化，不可直接与CPU PPO环境步/秒作训练倍速比较。探针 `probe_mujoco_warp.py`、`compare_warp_dynamics.py`、`benchmark_warp_physics.py` 不影响现有CPU训练。要实际迁移，需要将舵机控制、任务环境、并行奖励、观测、重置等改为GPU批量计算，验证容量、物理一致性、显存和完整训练速度。

## 稳定性问题和 GPU 训练试验
2026-11-01，在实现GPU舵机对照时发现原理论控制器第五轴阻尼增益0.08配合候选轴惯量1e-6 kg·m²与0.5 ms步长，出现最大约260 rad/s的数值振荡和频繁力矩饱和。先前使用原控制器的CPU训练结果因此不能作为可靠步态证据。原连续训练已停止，旧检查点保留。

`stabilized_servo.py` 将第五轴的假设阻尼增益暂改为0.01，其余轴保持0.08；这是数值实验参数，非实测值，不代表物理舵机。三组4秒、35%虚拟托举的固定动作对照中，CPU/GPU状态未见非有限值；观测、接触与奖励仍有浮点和接触差异。角速度观测须按现有CPU实现使用惯性框架 `ximat`，不是机身 `xmat`。

`train_stabilized_cpu.py` 以新控制假设从头训练8个CPU环境，进度写入 `stabilized_state.json`、`stabilized_audits.jsonl`。`warp_vec_env.py`、`train_warp_continuous.py` 在RTX上实验性并行32环境，使用相同候选模型和稳定化舵机、逐环境重置、接触及奖励计算，并每两轮使用稳定化CPU环境评估；GPU进度写入 `warp_training_state.json`、`warp_training_audits.jsonl`。GPU逐控制步检查 `Data.overflow`；实验仍需更长时间、随机工况、接触和重置准确性验证，不得用于实物。

单次4096环境步短测，在当时同时运行CPU对照和可视化的条件下，32环境GPU PPO约743环境步/秒，8环境CPU对照约281环境步/秒；并行数量、精度与负载不同，不是严格同条件或长期速度保证。单次32768步GPU训练约786环境步/秒（不含独立CPU评估），该策略在三次4秒CPU评估中无有效抬脚。

`查看GPU四画面.bat` 显示32个GPU训练环境中前4个的共享内存状态；`查看四画面和训练进度.bat` 显示8个CPU对照环境的状态。两者为真实训练环境的周期快照，均施加所示虚拟辅助。双击 `停止持续训练.bat` 停止两条训练，上一轮已保存检查点保留。

GPU持续分支通过检查点 `warp_training_current.zip` 续训，每32768步保存；每两轮在CPU稳定化模型上独立评估有辅助和无辅助策略，全部评估满足站立、前进及交替抬脚门槛后才将托举降低5个百分点。三次评估未改善时回退较好检查点并调整弱侧抬脚奖励。第4轮（163840环境步）GPU训练环节约717步/秒，CPU评估3个有辅助及3个无辅助工况均未触发摔倒，但都没有有效抬脚，故仍为50%托举。该速度不含CPU评估、重启及整体使用时间。CPU评估时策略临时切到CPU，结束后切回CUDA；已验证切换及后续训练均正常。此分支和CPU对照均使用暂定稳定化参数，绝不可当作实物安全验证。
