# Windows：使用 VS Code 和 PlatformIO 烧录 ESP32

本说明适用于本仓库当前的经典 ESP32 DevKit / ESP32-WROOM 系列工程。`board = esp32dev` 不是 ESP32-S3 的配置：如果实物是 S3 或其他型号，先确认板型再调整配置。项目的主程序此前据仓库记录已编译通过，但尚未在实物上完整验证；本说明编写时未重新编译或连接硬件。

## 1. 准备软件和工程

1. 安装 [VS Code](https://code.visualstudio.com/)，按 `Ctrl+Shift+X` 打开扩展，搜索并安装 **PlatformIO IDE**。等待初始化完成，必要时按提示重启 VS Code。
2. 获取本仓库：在 GitHub 仓库页面点 **Code → Download ZIP**，下载后右键“全部解压缩”；或在已有 Git 的电脑上克隆：

   ```powershell
   git clone https://github.com/kdwbll/Biped_Robot.git
   ```

3. 在 VS Code 中选择 **文件 → 打开文件夹**，按下表选择要烧录工程的文件夹。打开的文件夹内必须直接能看到 `platformio.ini`。三个工程相互独立；每烧录一个，都会替换开发板上原有程序。

| 工程文件夹 | 作用 | 何时使用 |
| --- | --- | --- |
| `firmware/hardware_tests/i2c_scan` | 扫描 I²C 地址；源码 `src/main.cpp` | 确认传感器接线后，检查是否能发现模块 |
| `firmware/hardware_tests/servo` | 电脑串口命令测试单个舵机 | 核对舵机电源和控制信号后，拆离机构测试 |
| `firmware` | 双足机器人主固件 | 单项测试及接线核验完成后的受保护联调 |

打开 `firmware` 时不要将测试工程的 `src/main.cpp` 复制进主工程。要换工程时重新“打开文件夹”，确认选择的是对应的 `platformio.ini`。

## 2. 核对配置并编译

目前各工程均配置 `platform = espressif32@8.0.0`、`board = esp32dev`、`framework = arduino`；主工程使用 ESP32Servo 3.2.1、Ramp 0.7.0 和 SparkFun BNO08x 1.0.6。保留工程自带配置，不需要新建工程或复制原始 `.ino` 文件。

首次打开时 PlatformIO 需要联网安装工具链和依赖，可能花费几分钟。点击状态栏的 **✓ Build**；也可以在左侧 PlatformIO 图标中选择当前工程的 **Project Tasks → esp32dev → General → Build**。出现 `SUCCESS` 表示该次编译成功；编译不需要接板。若失败，保存终端末尾完整错误、工程路径和配置版本后再排查，不要把红色提示直接当成已完成。

## 3. 连接开发板与上传

1. 先断开舵机电源，USB 单独连接 ESP32 和 Windows 电脑，使用可传数据的数据线。到 Windows **设备管理器 → 端口（COM 和 LPT）**查看新出现的 `COM` 端口；拔插对比可以辨认。无端口时检查数据线、接口，以及开发板实物 USB 转串口芯片对应的官方驱动；USB 线插入位置以实物为准。
2. 点击 **→ Upload**（或 Project Tasks → General → Upload）。PlatformIO 会先编译，再写入已选串口；出现 `SUCCESS` 才表示工具报告上传完成，并不等于硬件运行已验证。
3. 如有多个端口或自动识别错误，可在当前工程 `platformio.ini` 的对应环境下加入 `upload_port = COM5`，将 COM5 换成设备管理器实际端口；串口监视器也可用 `monitor_port = COM5`。不同工程分别配置，别把示例端口当成固定值。
4. 如果一直显示 `Connecting...`，先关闭其他占用该串口的程序，确认端口、线材与供电。仍失败时，可在上传开始连接期间按住开发板 **BOOT**，连接建立后松开；具体按键与时机依板卡而异。完成后如未自动运行，可按 **EN/RESET** 重启。

## 4. 查看串口输出

点击 PlatformIO 状态栏插头图标 **Serial Monitor**，或 Project Tasks → General → Monitor。设置 **115200 波特率**；测试工程已配置 `monitor_speed = 115200`，主工程 `Serial.begin(115200)`，如主工程显示乱码可在其 `platformio.ini` 增加该设置。乱码还需检查端口与串口设置。准备重新上传时先关闭监视器，避免串口占用；终端监视器可按 `Ctrl+C` 退出。

## 5. 推荐测试顺序

### I²C 扫描

断电后，确认所购 BNO 模块的电压、逻辑电平、I²C 模式、地址和接线。扫描程序使用经典 ESP32 的 **SDA GPIO21、SCL GPIO22**；还需连接合适电源与 GND，以具体模块电路为准。上传 `i2c_scan` 后打开 115200 监视器，程序每 5 秒扫描；出现 `Found: 0x..` 仅表示该地址有应答，不代表姿态数据正确。

主程序当前设置地址 **0x4B**、INT **GPIO19**、RST **GPIO18**，并调用 `Wire.begin()`；实物地址和模块引脚须确认，若不匹配应按实际调整源码并重新编译。不要将 VIN、I²C 或复位线照搬到未经核实的模块。

### 单舵机

舵机先从连杆拆下并固定本体。断电确认舵机允许电压和极性；舵机用适当独立电源，信号接 GPIO13，电源负极与 ESP32 GND 共地，不能用 GPIO 或开发板供电脚给舵机供电。USB 为 ESP32 供电时，避免另外同时向板上 5V 输入供电，除非板卡供电切换设计已确认。上传 `servo` 测试工程后开 115200 串口监视器，输入并发送带换行的命令，依次尝试：

```text
1500
1450
1550
off
```

程序要求先发送 `1500` 才启用脉冲；仅接受 `1500`、`1400`、`1450`、`1550`、`1600` 和 `off`。`off` 只停止脉冲，不切断电源，也不保证卸力。数值是脉宽微秒，不是角度；即便接近中位也不能保证所有舵机或机构安全。异常立即切断舵机电源。

### 双足主程序

单项测试完成后重新打开 `firmware`，Build 和 Upload 主工程。**首次不要让机器人落地自由行走**：检查供电、零位、动作范围，使用可靠支撑并逐步测试。当前主程序通过 ESP-NOW 接收遥控结构数据，尚无电脑串口控制和断线保护；打开串口监视器不会自动变成键盘遥控。源码中 servo2/servo4 的左右注释不一致，偏移量不是实机标定值；IMU 初始化失败会停在错误提示。先核实实物再调试。

更详细的到货调试顺序见 [到货后调试说明](到货后调试说明.md)。记录开发板型号、COM 端口、固件版本、传感器地址、电源电压、舵机型号和测试结果，方便复现与排错。
